### Retry boundaries

Atomic generic response receipts cover `POST /recipes`, `/meal-plan`, `/collections`, `/shopping-lists`, `/pantry/products` and `/pantry/batches`. These use synchronous shared services on the same SQLite connection. A session request without an idempotency header remains supported and has no receipt guarantee. Other mutations retain their own domain contracts; this is not a claim of global exactly-once execution.

Reviewed catalog confirmation uses the existing food import operation table. Its commit is separate from reads: search, barcode, details, measures, guidance, chains, store search, retail evidence and enrichment create no local product, stock, purchase or intake. Shopping confirmation imports/matches the reviewed source and records Bòrd cart intent; it does not purchase, unpack, log consumption or modify any retailer basket.

A new import requires the reviewed exact source revision. Expired or missing revisions require review again. A completed exact retry returns its saved result during a catalog outage. A different normalized intent or actor must not reuse the operation. Older pre-account-binding receipts cannot gain an account binding retrospectively; their compatibility replay still requires their original profile and exact digest.

Native unresolved scan commands and chat drafts stay in memory, scoped to the account/instance. Closing/reopening chat preserves them; logout clears them. An app process kill does not persist sensitive drafts or scanner commands. Server-owned chat turns are reloaded and a running turn blocks a new request in that conversation even without the old client command. Device process-kill scanner recovery remains an explicit limitation; users must inspect saved stock/list state before a new scan command after restart.

### Native dependency advisory limit

Compatible refresh reduced the initial audit from 44 advisories (including one critical) to 30 (22 high, 8 moderate, zero critical). Remaining direct advisory sources include `braces`, `node-forge`, `sprintf-js`, `decode-uri-component` and `image-size`, with transitive propagation through the Expo/Metro toolchain. At inspection, the latest published braces/node-forge/sprintf-js versions were still within the advisory ranges. Other remediation suggestions required incompatible dependency lines or forced SDK changes. No forced downgrade to Expo 44 or unverified React Native/Router major upgrade was accepted to make an audit count green. This remains a material dependency/release risk requiring supported upstream patches or a separately verified SDK upgrade; bundling does not resolve advisories.

### Checks not established by this evidence

Native camera permission, real scanner input, SecureStore/platform lifecycle, live session/password/passkey/email, VoiceOver/TalkBack, dynamic type, keyboard/safe-area behavior and iOS/Android device UI have no direct runtime evidence here. Deterministic stream tests prove progressive parsing and state contracts, not device rendering. No Docker/Unraid deployment, real provider dataset readiness, source acquisition, retailer writes, paid AI output or production operational health is claimed.
