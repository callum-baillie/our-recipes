# Capability matrix

**Snapshot:** application source `0e56ca0` on `refinement/post-review-completion`, reconciled from starting `160441dd74ef79dab936a34a0f1c5e74065311c1`. This is implementation coverage, not a claim that each native screen or live service has been exercised. Current acceptance and the final committed revision belong to the [post-review register](post-review.md); earlier release evidence remains historical.

The inventory in [inventory.json](inventory.json) locates the current web routes, native routes, application APIs, services and curated assistant operations. This matrix describes user workflows rather than counting HTTP verbs. A POST lookup is a read. Device rendering, deployment readiness and live provider quality are separate from source presence and deterministic contract evidence.

## Count definitions

The source inventory records **175 API route patterns / 253 explicitly exported HTTP handlers**, **45 web page modules**, **77 service modules**, and **67 Expo route-tree files**: **58 screen-route files + 9 layouts**. The 22 files in `mobile/src/screens` also include shared screen helpers and are not 22 additional routes. The non-API `/barcode-decoder` handler is listed separately. A catch-all authentication route is one pattern, not a count of every auth-library operation.

There are **21 direct assistant function declarations** and **112 curated application operations** dispatched through those functions: **39 read, 72 write, 1 paid**. These are separate, overlapping layers, not 133 independent assistant tools. Ten read operations use POST. The API-key allowlist has **104 route patterns / 142 allowed method-resource-action combinations**; it does not grant session-only capabilities. No source module currently declares a React `use server` action; the existing HTTP/service contracts are reused instead of adding duplicate routes for table coverage.

## Deliberate boundaries and remaining checks

- **Read versus commit:** search, barcode, portions, guidance, enrichment and directory lookup are reads even when implemented as POST. Import, stock creation, cart replacement, purchase intake, diary intake and store linking each need their own reviewed operation and permission. Selecting a source measure changes a form draft only.
- **Native parity is named per workflow:** native supports reviewed scanner imports/local matches, local store/route editing, streaming chat and editable proposals. Official store-directory filtering/linking uses the visible same-instance web handoff. Identified enrichment is available through the native assistant's catalog read tool, not a dedicated native manual control. Native Nutrition now has an exact-source portion picker backed by the authoritative saved-record context. It offers grams only when the server supports that conversion, preserves entered drafts until explicit selection, and pins the reviewed record at confirmation. These are explicit surface differences, not inferred feature parity from API presence.
- **Recovery is bounded:** scanner journals retain the original normalized command and receipt key; chat journals retain only an authorized server reference. Account, instance and original actor must match before recovery. Reconnection never automatically resends work. Private text/attachments remain memory-only and are not promised to survive process loss.
- **Protected handoffs:** installation credentials, backup/restore/reset and fresh-identity security operations remain on their guarded surfaces. Binary exports open protected app destinations; a file download does not grant a model or API key broader access. Provider acquisition and retailer checkout are not ordinary application capabilities.
- **Evidence:** final root gates and production-browser results belong to the current register. This workstream records 70 passing native tests across 16 files, passing native formatting/types/lint, 16 focused native portion/catalog checks, 6 root portion-contract checks and a 20-case root-owned product-context/intake integration pass. Both final native bundles export at 6.31 MB; see [catalog/native evidence](post-review-catalog.md). These results do not establish physical-device behavior or live dataset readiness.
- **Blocked external verification:** no attached Android device/emulator or iOS/macOS simulator is available. Camera permission/scanning, OS handoffs/login, Keychain/Keystore process-kill retention, TalkBack/VoiceOver, dynamic type and keyboard/safe-area behavior remain unverified. Live source-pack readiness, live auth/email/passkey flows, paid-image realism and deployment are separate checks.
