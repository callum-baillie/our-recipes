## API scope

The registry declares 120 operations across 86 paths, including a compatibility alias. Core workflows include recipe history/restore, preferences/favorites, imports/exports/images, pantry stock actions and mappings, cooking, meal-plan batch/copy/swap/status/refresh/export, shopping intake/restock/aisles/supermarkets, and collection ordering.

Workflow settings are opt-in read/update grants. Existing default keys do not gain settings access. API-key actions are attributed to the owning account's profile through ActorContext. Exact trusted-origin checks remain required for session mutations.

Account administration, backup/restore, personal nutrition diaries and health profiles, theme/branding, and assistant conversations/proposal confirmation remain session-only. Shared recipe/product nutrition is available to integrations. See [API conventions](api.md) and [OpenAPI](openapi.yaml) for the supported contract and per-operation permissions.

## Validation

- Unit suite: 332 passed across 61 files.
- Integration suite: 240 passed, 9 skipped across 47 files. Rerun with two workers after resource contention caused timeouts during concurrent browser compilation.
- Real Better Auth tests exercise old-session confirmation, key creation, bearer authorization without cookies/origin, permission failures, rotation, expiry, rate limiting, cross-resource pantry grants, and proxy boundaries.
- Registry tests check every declared operation against its actual authenticated handler.
- OpenAPI lint, route coverage, and generated-client contract smoke passed (142 documented operations).
- TypeScript checking and source ESLint passed.
- Production release build and artifact verification passed: 2,917 packaged files checked. The first artifact check exposed the copied dotenv file; the corrected pipeline passed end to end.
- Chromium checked API settings, recipes, pantry, planner, and lists at 1440×1000 and 390×844: no horizontal overflow or uncaught page errors in the final run.
- Axe WCAG A/AA checks found no violations on those five desktop screens.
- Browser interaction checks passed for old-session → confirm identity → create key, and planner network failure → error feedback → usable controls.

Browser checks used a temporary SQLite database with synthetic household data and disabled external providers. No live OpenAI call was made. Docker, deployment, backup restoration, PWA installation, and mobile native builds were outside this review's validation. Passkey hardware and live email delivery were not exercised.
